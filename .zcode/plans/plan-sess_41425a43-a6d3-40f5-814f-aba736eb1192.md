目标：把计算器库从现有 43 项扩成“成人 ICU/急诊高频优先”的分批 backlog。所有新计算器都遵守同一原则：计算器板块可独立手算；病历板块通过 AssistantService 的 DATA_FIELDS / CALC_INPUT_SPECS / callEngine 识别到数据后自动计算/刷新；不改数据库结构，继续用 patient_data 通用存储。

范围结论：
- 纳入：之前我建议的缺口 + RTS/RSBI/HELLP + 参考 MDCalc 后评估出的成人 ICU/急诊高频项。
- 不纳入或低优先：儿科、产科常规、门诊一级预防、精神量表、骨科/急诊 MSK 规则、风湿/肿瘤专科评分、重复慢性分期。NEWS2 已有，不重复；MEWS 只作可选 legacy。WELLS PE 已有，WELLS DVT 作为独立 DVT 专项才加。HELLP 按你的要求纳入，但实现为“标准核对/分层”，明确非最终诊断。

统一落线方式（每个计算器都一样）：
1. `model/CalculatorRegistry.ets` 注册 id/name/enName/group/icon/kw/description/whenToUse。
2. `engine/*Calculator.ets` 加纯计算函数，返回 CalcResult；阈值、单位、适用场景写进 footnote。
3. `components/calculators/*Calculator.ets` 用 CalcCard/SectionTitle/ResultCard/ResetButton 做独立 UI；不硬编码颜色，沿用 AppColors。
4. `pages/Index.ets` import + currentCalc 分支；第一批先沿现有 if/else，若新增超过约 10 个再单独做 registry-driven router 重构，避免一次改动过大。
5. `services/AssistantService.ets`：import engine；补 DATA_FIELDS；加 CALC_INPUT_SPECS；加 callEngine 分支；必要时加 FIELD_KEY_ALIASES/CALC_ID_ALIASES。
6. `model/Patient.ets` DATA_DOMAINS 补字段到对应域；不新增 domain 就不动 DOMAIN_COLORS。
7. `CalcKbLinks` 不改代码，靠 registry name/group/kw 自动挂知识库。

批次计划：
Batch 1a：用户点名 + 极低输入负担快速项
- RTS 修正创伤评分：gcs/sbp/rr，gcs 可由 E/V/M 推导。

- qSOFA：作为 SOFA 的轻量衍生视图，rr/sbp/意识或 gcs。
- 校正钙 + AG/Delta Gap/Osmolal Gap 组合：ca/alb、na/cl/hco3、glu/bun/na/ measured osm（可选手动）。

Batch 1b：之前建议的 P0/P1 临床缺口
- HEART Score：history/ecg/age/risk factors/troponin；补 ctni/tropUln/ecg/history/riskFactorCount 字段。
- Glasgow-Blatchford GBS：bun/hgb/sbp/hr/melena/syncope/liver/heart failure。
