# 独立诊断 Tab — 项目背景与进展

> 编写时间：2026-07-28
> 用途：让新加入的 LLM 或开发者快速理解项目上下文、已有资源、当前进展

---

## 一、项目起源：MedCalc 的进化史

MedCalc（重症智算）是一个 HarmonyOS 原生 ICU 临床计算器套件，其功能演进清晰地反映了临床需求的层层递进：

### 阶段 1：血气分析计算器
- 最初只是一个血气分析计算器
- 解决单一临床问题

### 阶段 2：88 个计算器 → 覆盖全 ICU
- 逐步扩展到 88 个临床计算器，覆盖 ICU 主要场景
- 问题：**计算器太多，医生不知道每个计算器是干嘛的，用不起来**

### 阶段 3：LLM 推荐计算器
- 加入 AI 推荐功能：输入患者数据，LLM 推荐应该用哪个计算器
- 问题：**手动输入太麻烦，医生不愿意逐项填数据**

### 阶段 4：LLM 识别全自动计算
- 上传检验报告图片/PDF，LLM 自动提取数据 → 自动填入计算器 → 自动出结果
- 问题：**同一个病人的检查结果是逐步出来的，需要统一存储和管理**

### 阶段 5：患者病历系统
- 加入患者管理功能，统一存储所有计算结果、检验数据、上传记录
- 加入知识库，为计算结果提供指南依据

### 阶段 6（当前）：诊断模块不够扎实
- 现有诊断功能：藏在患者详情页里，60+ 条诊断规则，按来源分组
- 问题：**诊断只是规则的副产品，没有被当作独立的一级功能来设计**
- 目标：**做一个独立的诊断 tab，把藏在代码中的诊断内容放到前台，清晰化、条理化、严谨化**

---

## 二、诊断 Tab 的定位

### 不是什么
- 不是又一个计算器（不产出新的"风险评分"）
- 不是患者相关的（不依赖患者上下文）

### 是什么
- **诊断规则浏览器** — 一个与患者无关的独立 tab
- 把现有的 60+ 条诊断规则从代码里拿出来，放到前台展示
- 按临床系统组织，让医生可以浏览、学习、理解诊断标准

### Tab 位置
5 个 tab 的顺序：**计算器 / 病历 / 诊断 / 知识库 / 设置**

## 三、现有诊断系统的技术现状

### 核心代码文件

| 文件 | 用途 |
|------|------|
| `model/DiagnosisRules.ets` | 60+ 条诊断规则定义（感染/呼吸/心血管/神经/肾脏/肝/血液/内分泌/营养） |
| `services/DiagnosisEngine.ets` | 规则匹配引擎（全命中=confirmed, 部分命中=partial, 化验异常=labAlert） |
| `model/Patient.ets` | PatientDiagnosis 模型（source: rule/user/partial/llm_hint） |
| `components/patient/DiagnosisKbSection.ets` | 诊断关联知识库展示组件 |
| `components/patient/DetailPageViews.ets` | 诊断详情页（按来源分组展示） |

### 规则引擎的工作方式
- 每条规则包含：field + operator + value
- 支持两种数据源：**原始数据字段**（如 `pao2 < 60`）和**计算器结果**（如 `calcResult:sofa >= 2`）
- 匹配结果分三类：confirmed（全命中）、partial（部分命中，≥50%条件）、labAlert（单指标异常）

### 已有诊断规则覆盖（约 60 条）
覆盖 9 个领域：感染、呼吸、肾脏、心血管、神经、血液、肝、代谢、营养

## 四、诊断底座的设计思路

### 核心决策：用 ICD-11 重建底座

我们决定**不用 ICD-10 做基座，而是用 ICD-11**。理由：

| 对比 | ICD-10 | ICD-11 |
|------|--------|--------|
| 编码数 | 2,047（WHO原版） | 27,502 有效码 |
| 时效性 | 1990 年代标准 | 2019 年 WHO 通过，持续更新 |
| 中文版 | 无官方中文（只有翻译版） | 有 WHO 官方中文版 |
| 章节 | 19 章 | 26 章（含传统医学） |
| 编码格式 | A00-Z99 | 1A00 格式，全新体系 |

### 底座结构

```
诊断底座 = 12 大类 / ~73 实体
    ├── 底层数据 = ICD-11 完整编码（27,502 码，作为引用字典）
    ├── 筛选层 = ICU 相关编码（约 923 码）
    ├── 展示层 = 73 个诊断实体（按临床系统组织）
    └── 覆盖层 = 规则状态 + 知识库状态 + 优先级
```

### 12 大类和实体数

| 大类 | 实体数 | 说明 |
|------|--------|------|
| 感染与脓毒症 | 11 | 脓毒症、SIRS、肺炎、VAP、结核、真菌、肝炎、HIV、CNS感染、肠道感染 |
| 呼吸系统 | 10 | ARDS、呼衰、COPD、哮喘、肺栓塞、胸膜疾病、肺脓肿、吸入性肺炎、肺萎陷、间质性肺病 |
| 心血管 | 12 | AMI、心衰、心律失常、心脏骤停、高血压急症、心源性休克、肺心病、主动脉夹层、DVT、心内膜炎、心肌炎、心包疾病 |
| 神经 | 9 | 脑出血、脑梗死、癫痫持续状态、谵妄、昏迷、颅内高压、GBS、重症肌无力危象、TIA |
| 肾脏 | 7 | AKI、CKD、肾小球疾病、肾小管间质疾病、泌尿系结石、UTI、RRT指征 |
| 消化与肝 | 7 | 肝衰竭/ACLF、肝硬化、肝性脑病、上消化道出血、急性胰腺炎、肠梗阻、腹膜炎 |
| 血液 | 5 | DIC、凝血功能障碍、血小板减少、贫血、粒细胞缺乏 |
| 内分泌与代谢 | 7 | DKA、低血糖、甲亢危象、肾上腺危象、水电解质紊乱、横纹肌溶解、肿瘤溶解综合征 |
| 营养 | 1 | 营养不良 |
| 症状与体征 | 4 | 心血管呼吸症状、神经症状、发热、休克 |
| 损伤/烧伤/中毒 | 2 | 烧伤、中毒 |

## 五、为什么现在要挑选指南

诊断底座需要两个核心要素：
1. **ICD-11 编码** → 已解决（从 ICD-11 中文版 xlsx 中提取）
2. **诊断标准（阈值）** → 需要从指南/共识中提取

### 诊断标准 ≠ 指南全文

我们需要区分两类资源：

| 类型 | 特征 | 举例 |
|------|------|------|
| **定义型文献** | 直接给出诊断阈值 | Berlin ARDS 定义、KDIGO AKI 分期、Sepsis-3、GOLD COPD 分级 |
| **治疗型指南** | 讲怎么治，诊断标准需另找 | ESPEN 营养指南、血小板输注指南、CRRT 抗凝指南 |

### 指南的用途

- 为每个诊断实体提供**权威的诊断标准来源**
- 供诊断 tab 展示"依据：XX 指南 YYYY"
- 供病历诊断板块链接到具体指南章节
- 为后续知识库重建提供内容素材
