# ICU 知识库检索方法设计（建议稿）

> 版本：2026-07-22
> 定位：课题"指南即时自动检索"主路线的详细技术设计，供申报书修改与后续实现共用
> 依据：MedCalc 已上线检索实现（`services/KnowledgeService.ets`）+ PITFALLS.md 检索踩坑记录 + 申报书技术路线五步流水线的评估结论
> 状态：建议稿，未实现部分已标注

---

## 1. 设计目标与原则

**目标**：输入一个诊断名（或症状/问题），在有限上下文预算内，从知识库中检出**临床相关**的条目，产出**每条均带可验证原文出处**的结构化建议。

**四条原则**（全部来自已验证的教训或申报书承诺）：

1. **召回靠扩展，精度靠核心词**——扩词只负责"不漏"，原始查询词始终掌握排序主导权（PITFALLS 07-10：纯 OR 扩展会把"社区获得性肺炎"稀释成"肺炎"匹配 40+ 篇）
2. **先元数据收窄，后全文检索**——全文索引跨主题噪声无解（"肺炎球菌脑膜炎"不是肺炎文章），元数据（标题/标签/摘要/链接）天然只含文章自身主题
3. **LLM 只做判定与翻译，不做计算与引用发明**——相关度验收、内容提取交给 LLM；引用是否真实存在由**程序**校验，与"AI 仅翻译官"原则一致
4. **每一级都有降级路径**——任何一级空召回/失败都不能让流水线断掉，必须有明确的兜底去向

**上下文预算**：按本地可部署模型可用上下文数万 token 级设计（不按厂商宣传值），单次送入 LLM 的候选内容控制在可全量精读的规模，宁可分批不可溢出。

---

## 2. 总体架构：五级流水线

```
诊断/问题输入
   │
   ▼
[L1 查询规范化+扩词] ──确定性──► 核心词集合（原始诊断名）
   │ LLM                            │
   ▼                                │
[L2 元数据匹配] ◄──────────────────┘（核心词优先排序）
   │ FTS5(标题+标签+摘要+路径+链接)
   ▼
[L3 范围内全文检索]（在 L2 命中的条目/章节内）
   │
   ▼
[L4 相关度验收]（LLM 二元验收：文章主题 vs 查询主题）
   │
   ▼
[L5 提取归纳+引用校验]（LLM 提取四类建议；程序校验引用路径真实存在）
   │
   ▼
结构化建议（病理生理/诊断要点/检测评估/治疗建议，逐条带出处）
```

与申报书五步的对应：L1=第一步扩词、L2=第二步目录匹配、L3=第三步全文检索、L4=第四步验收、L5=第五步提取归纳。**相比申报书新增三个机制**：核心词过滤（L1→L2 之间）、空召回降级链（各级）、引用确定性校验（L5 内）。

---

## 3. 分级详细设计

### L1 查询规范化 + 扩词

**输入**：诊断名（来自四类诊断：匹配/疑似/LLM 补充/用户诊断）或自然语言问题。

**两步，顺序不可换**：

1. **规范化（纯程序）**：
   - 复合实体保护：先提取受保护的复合词（"社区获得性肺炎""医院获得性肺炎"等，维护 COMPOUND_PREFIXES 清单），再对其余部分做停用词剥离。**停用词表必须用已知复合实体回归测试**（PITFALLS：剥离"获得性"曾毁掉 CAP 特异性）
   - 产出**核心词集合**：原始诊断名的语义核心（如"社区获得性肺炎"→{社区获得性肺炎， CAP}）
2. **扩词（LLM）**：同义、近义、上下位、英文缩写、中医对应、临床相关并发症/机制（"慢阻肺→COPD、AECOPD、Ⅱ型呼衰、肺心病"）
   - 扩展词打标区分"等价词"（同义/缩写，可参与核心匹配）与"相关词"（仅用于召回，不参与核心匹配）
   - LLM 输出为结构化 JSON，程序解析失败时降级为仅用核心词

**输出**：`{核心词[], 等价词[], 相关词[]}`

### L2 元数据匹配（第一级召回）

**索引**：FTS5，仅索引元数据：`标题 + 标签 + 摘要 + 路径关键词 + wikilink 目标`。全文单独存 `kb_content`，**不进索引**。

**知识库侧配套要求**（此级效果的全部前提）：
- 每页 YAML frontmatter 必须有 title/tags/summary；summary 只写本页主题，**跨主题疾病名必须清洗**（"肺炎链球菌"→"S.pneumoniae(肺炎双球菌)"、"AKI"→"SA-AKI"作用域标签，PITFALLS 07-10 已验证必要性）
- 新页面入库时由"LLM 生成 + 人工抽检"注入标签；标签注入用固定清单约束，避免标签发散

**匹配与排序**：
1. 用核心词∪等价词∪相关词做 OR 召回（保召回）
2. **核心词过滤排序**：命中核心词的排最前；仅命中相关词的降级（PITFALLS 已验证此机制必要性）
3. 数量控制：核心命中取 Top N（建议 N=10），不足时以相关词命中补齐到 N
4. 强制纳入教材兜底条目（实用重症医学相关章、病理生理学）——但标记为"兜底"，在 L4 验收中适用更严标准

**空召回降级**：核心词+等价词零命中 → 放宽为全词 OR 取 Top N → 仍为零 → 直接以教材层全文检索兜底并标记"低置信"，**不中断流水线**。

### L3 范围内全文检索（第二级召回）

**范围**：仅在 L2 命中条目的页面/章节内执行全文检索——这是与"全局全文索引"的关键区别，范围内噪声已被 L2 预先过滤。

**方法**：在命中页面的 `kb_content` 全文中，按核心词+等价词做段落级匹配，检出候选片段（段落或固定窗口 ~500 字）。
- 每页最多取 3 个片段，全局候选片段总数控制（建议 ≤30，约对应上下文预算）
- 页面结构允许时按章节锚点切分，保留"片段→章节"的归属关系（L5 引用要用）

**输出**：`[{页面, 章节, 片段文本, 匹配词}]`

### L4 相关度验收（LLM 二元判定）

**做法**：对每个候选条目（不是片段）做**二元验收**——"这篇文章的主题是不是关于 X？"而非"这段文字提到 X 吗？"（PITFALLS：验收是接受/拒绝过滤器，不是重排）
- 输入：查询 + 条目的元数据（标题/标签/摘要），**不送全文**——元数据判定成本低、噪声少
- 兜底条目适用更严标准：教材章节若主题不直接相关，仅在其能提供"机制解释"时保留（对应申报书"理解问题"的定位）
- LLM 判定失败/超时：保守策略——保留但标记"未验收"

**输出**：通过验收的条目集合及其片段。

### L5 提取归纳 + 引用确定性校验

**提取（LLM）**：对通过验收的片段，提取四类结构化建议：病理生理 / 诊断要点 / 检测评估 / 治疗建议；同时归纳总结。每条建议必须附：`{来源页面, 章节, 原文片段引用}`。

**引用校验（纯程序，本设计相对申报书的关键新增）**：
1. 校验来源页面路径在知识库中真实存在
2. 校验章节锚点在该页真实存在
3. 校验"原文片段引用"是来源页面的**子串**（或高度模糊匹配）
4. 三项全过 → 标记"已验证"；任一不过 → 该条建议**不展示**或降级为"来源待人工核对"

这一步把"LLM 幻觉式引用"（编造不存在的章节）在展示前拦截，是"所有建议附带原文出处"承诺的确定性保障——与评分计算由程序锁定是同一哲学。

**输出**：带"已验证出处"的结构化建议集。

## 4. 症状/体征类查询的特别处理

诊断名以外的查询（"血小板减少""发热伴皮疹"）会被多病种文章淹没（PITFALLS 待办 RULE_SEARCH_HINTS）。处理：

- 维护**症状→定向词映射**（RULE_SEARCH_HINTS）：症状词检索时附加鉴别诊断定向词（"血小板减少"→定向"DIC/ITP/TTP/HLH 鉴别"），使 L2 匹配落向鉴别诊断类条目而非各病种条目
- 症状类查询在 L4 验收时标准放宽（鉴别诊断场景天然多主题），但 L5 引用校验不变

## 5. 质量指标与评测方法

检索质量必须用数据说话，建议建立**评测集**（第一年上半年，与 20–50 份病历预实验同步）：

| 指标 | 定义 | 目标值 |
|---|---|---|
| Top-5 目录命中率 | 人工标注的"正确条目"出现在 L2 Top-5 的比例 | ≥85% |
| 验收通过率 | L4 通过条目中人工判定真相关的比例（精度） | ≥90% |
| 引用校验通过率 | L5 引用三项校验全过的比例（幻觉引用率=1-此值） | ≥95%（不达标则该功能不上线） |
| 端到端有用率 | 抽样查询的最终建议被临床医生判为"有用"的比例 | 预实验确定基线 |

评测集：选 30–50 个查询（覆盖高频诊断/边缘诊断/症状查询各 1/3），人工标注正确条目，作为每次检索改动后的回归基准。

## 6. 知识库覆盖与检索的关系

检索方法解决不了"库里没有"。配套覆盖策略（另见覆盖率测算）：

- **覆盖面自顶向下**：以 ICD-10 ICU 清单为目录、按科室流行病学排序决定补哪些指南，不从指南出发长覆盖
- 当前缺口：55 条诊断规则中约 30%（15–18 条）无对应文献 → 优先补 25–30 部（VTE/PE、肝硬化并发症、高血压急症、内分泌危象、输血/贫血、院感相关 CLABSI/CAUTI/真菌/耐药菌）
- **规则判定标准自底向上**：每条规则的阈值引自指南/学会定义，`references` 链到具体章节——规则层与检索层共用同一套"可验证出处"机制

## 7. 对申报书技术路线的修改建议（可直接摘用）

原文五步保留，建议做四处增补：

1. 第一步后增加："**以原始诊断名为核心词，扩词结果仅用于召回；检索排序以核心词命中优先，扩展词命中降级，防止扩词稀释特异性**"
2. 第二步增加空召回降级："**目录匹配零命中时，降级为全局元数据检索并强制教材层兜底，结果标记低置信，不中断流水线**"
3. 第五步增加引用校验："**所有来源标注经程序校验——页面路径、章节锚点、引用片段三者均须在知识库中真实命中后方可展示，杜绝模型编造引用**"
4. "受限于 12.5 万至 100 万上下文"改为："**受限于本地可部署模型的可用上下文（数万 token 级），无法将知识库全量送入模型，必须分级收窄**"

## 8. 实施路线

| 阶段 | 内容 | 对应课题年度 |
|---|---|---|
| S1 | 补 25–30 部缺口指南 + newkb 7 部导入 + 教材剩余章校对；建 30–50 查询评测集 | 第一年上半年 |
| S2 | 服务端实现五级流水线（现有 smartSearch 逻辑迁移 + 核心词过滤 + 降级链 + 引用校验） | 第一年 |
| S3 | 评测集跑通四项指标；RULE_SEARCH_HINTS 症状定向；轻量模型验收/提取质量调优 | 第二年 |
| S4 | 与诊断引擎/预警闭环（"数据异常→计算确认→机制解释→诊断检索"）；病历预实验验证 | 第二~三年 |

**风险与降级**：轻量模型在 L4/L5 的判别质量是最大变量——若评测显示验收精度 <85%，降级方案为：L4 改规则过滤（核心词出现频次+位置启发式），L5 仅保留"程序可校验"的引用粒度（页面级而非片段级），即退回备用路线（经典 RAG + 程序校验出处），两路线共享知识库与确定性引擎，互不绑架。
